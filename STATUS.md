## Cross-cutting known issues and gotchas
- Typed `@export var x: Camera3D` loads as null from a `.tscn`. Verify any node export.
- A shader `vec3` uniform set from a `Vector3` is read as linear, even with `source_color`: pass palette colours as `srgb_to_linear()` (or set a `Color`).
- GDScript reads a property of a `const` preloaded resource once, at compile time (`const STATS := preload(...)`, then `STATS.x`), so live tuning never shows. Hold stats in a `var` or `static var` (all current cases are fixed; passing the const object on is fine).
- Reading another script's `static var` that holds a `preload`ed resource (`OtherClass.some_stats`) leaves GDScript 4.7 unable to clean up at exit: two `p_elem->_root != this` errors, and in some cases hundreds of leaked objects and resources. Keep such a var private (`_x`) and read it from outside through a `static func`. A small empty project didn't reproduce it, so the engine cause is unknown; check with `godot --headless --path . --quit-after 300`, which should print only the version line.
- GDScript 4.7: `Array[T]()` doesn't parse (declare a typed local first). A `const` can't hold `PackedVector3Array([...])`. Scalars passed to functions are copies, so return results. `(array[i] as PackedVector3Array).append(...)` appends to a copy: keep packed arrays in typed members.
